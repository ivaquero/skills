# draw.io → Visio (.vsdx) 保真转换与形状回归

**技能类型**：流程型 —— 管「先判定转换类型、按什么顺序生成、生成完怎么验、形状不对怎么回归」，不管图的内容、配色与版式设计。

输出恒为原生 OPC/VSDX（`Shape` + `Geometry` + `Text` 可编辑），不做位图化，不依赖 draw.io Desktop 或 Visio 安装；包内脚本只用标准库。

## 先固定四件事

1. **输入**：一批同编号的 `.drawio`，文件名即产物名。
2. **输出**：同名 `.vsdx`，与源文件放同一目录（或用 `--out-dir` 分开）。
3. **保真基准**：参考图或官方 stencil 定义。形状「对不对」以它为准，不以转换器的自绘预览为准。
4. **目录全部由命令行参数给出**。文档与脚本里不写本机绝对路径；技能包可能被复制或移植。

## 步骤

### 1 判定是「保真转换」还是「重跑旧生成器」

先列出目录里的 `.drawio` / `.vsdx` 与已有生成脚本，确认同名文件是不是同一套版式。同一项目里可能同时存在旧版 A4 知识建模图和中心放射式思维导图，二者同名但版式完全不同；此时要的是**以 `.drawio` 为输入的格式转换**，绝不能重跑旧生成器覆盖。

**完成标准**：明确写出「本次是转换 / 是重生成」的依据，以及产物是否与源文件同名配套。

### 2 盘点源结构

统计所有 `mxCell` 的 vertex / edge 数量、style 变体、特殊 shape、页面 `pageWidth/pageHeight`、坐标包围盒，并检查 HTML 文本、空节点、悬空边。据此定下形状映射表，不要边写边猜。

**完成标准**：四类节点（直角矩形、胶囊、圆柱体、波浪底文档）与关系标签的数量、样式取值、页面尺寸已列成表；连线的 `endArrow` / `endFill` / `endSize` 取值与带箭头边数已单独统计。

### 3 转换

```bash
python scripts/drawio2vsdx.py --in-dir DIR --out-dir DIR
python scripts/drawio2vsdx.py --in-dir DIR --only NAME --ppi 96
```

先用 `--only` 试转最密与最疏各一张，确认几何后再全量。单位、坐标翻转、形状映射、OPC 部件与兼容项见 `references/contract.md`；机器可判的几何基线见 `references/shape-rules.json`。

**完成标准**：每张图都有同名 `.vsdx`，转换器内置自检 0 失败。

### 4 静态校验

```bash
python scripts/verify_vsdx.py --drawio-dir DIR --vsdx-dir DIR
python scripts/selfcheck.py
```

前者逐文件核对编号一一对应、ZIP CRC、必需部件、XML 可解析、文本多重集、形状数、样式兼容项，以及四类形状的几何不变量（含 `Document` 的下角基线与 S 形波）；形状数按 `节点 + 2×带箭头连线 + 标签` 计算，并逐条检查箭头数量、闭合、填充色与尖端是否落在连线终点。后者校验技能包自身。`selfcheck.py` 用 `assets/minimal.drawio` 做真实往返，并故意压平 document 底边、删除全部箭头做两组反向测试，断言校验器能报错。

**完成标准**：两条命令退出码均为 0，反向测试确实抓到被破坏的形状。

### 5 反向渲染抽查

```bash
python scripts/vsdx_preview.py --in-dir DIR --out-html DIR/preview.html --png-dir DIR/png
```

脚本从 `.vsdx` 读回 Shape / Geometry / Text 自绘 SVG；`--png-dir` 需要 `rsvg-convert`。目视抽查主干最多与最少的两张，看中心结构、箭头方向、四类形状、中文与关系标签。这是**数据一致性**验证，不是 Visio 自身排版。渲染器只画 `pageN.xml` 里真实存在的 Shape，**绝不能**按 `EndArrow` 之类的单元格标记自行补画三角形——那会造成「预览有箭头、Visio 里没有」的自绘自验假象。

**完成标准**：无穿页连线、无形状拉伸、无文字溢出，四类形状可辨认；每条带箭头的连线末端都有可见实心三角，方向指向子节点。

### 6 「形状不对」时的回归闭环

不要凭印象改几何，按这个顺序走：

1. **放大对照**：从参考图裁出该节点放大，或查官方 stencil 的 path 定义，写清「应该是怎样 / 现在是怎样」。
2. **定位**：把产物里的 Geometry 反解成归一化 `(u, v)` 并放大渲染，找出偏差是波形周期、基线位置、还是端点被削掉。
3. **修复**：只改对应几何函数，同步 `references/contract.md` 与 `references/shape-rules.json`。
4. **全量重转**：形状函数一改，所有含该形状的文件都要重生，不能只修抽查的那张。
5. **新增机器断言**：把「对」的形状写成可判条件（点数、端点基线、值域、凹凸性），加入 `verify_vsdx.py`。
6. **反向测试**：故意破坏该形状，确认校验器能报错；否则断言是摆设。
7. **刷新预览并抽查整图**，确认修复没有引入新的遮挡或越界。

**完成标准**：新旧形状有放大对比；断言对全部同类节点通过（例如 58/58）；反向测试失败方向正确；工作日志与长期约定已写入这条形状规则。

### 7 判定产物过期与覆盖前备份

`zipfile.writestr` 写入当前时间戳，同一内容每次生成的**文件哈希都不同**。判断产物是否过期，把重算结果放到临时目录，逐部件比 ZIP 内解压后的字节，只报内容差异，忽略时间戳。覆盖前把现有 `.vsdx` 备份到带时间戳的目录。

**完成标准**：明确列出「实质差异文件数」与「仅时间戳差异文件数」，备份路径已记录。

### 8 交付

交付 `.vsdx`、预览页与转换脚本，说明命名规则、静态校验结果、以及尚未闭环的限制：Visio 自身打开是否实测、连线与箭头都是静态形状（不含 glue，移动节点不跟随）、圆柱体/波浪底/胶囊为折线近似。本机没有 draw.io Desktop/CLI 时不要擅自安装。

**完成标准**：用户能直接复跑转换，并清楚哪些是已验证、哪些只是静态校验与反向渲染的结论。

## 踩坑点

- **同名不等于同版式**。旧 `.vsdx` 与新版 `.drawio` 可能是两套布局，误跑旧生成器会把新图抹掉。
- **文本比对必须先归一化**。源里的 `<br>` 在 VSDX 里是真换行 `\n`，直接比文本多重集会把所有含换行的图误报成不一致。
- **别用 `RelEllipticalArcTo`**。A/B 传英寸绝对值会生成巨型弧面盖住整页；一律用归一化 `RelMoveTo` / `RelLineTo` 折线。
- **颜色写 `#RRGGBB`**，中文显式 `AsianFont`，Shape 不写 `Master="-1"`，否则导出全黑、中文错位或整页被静默丢弃。
- **连线几何要按 `dx/dy` 符号换算局部坐标**。固定 `(0,0)->(w,h)` 的骨架遇到向左或向下的边会把线画反。
- **document 不是三团向下鼓包**。正确形态是顶/左/右三边平直、左右下角为直角、底边一条完整 S 形波（`cycles=1`，两端落回 `base=1-size/2`）；`1-cos` 多周期波形既改错波形又削掉下角。
- **别只写 `EndArrow` 单元格**。自建 1-D `Connector` 无 Master、无 `BeginX/EndX`、无 `EndArrowSize` 时，Visio 不保证渲染该箭头（省略 `EndArrowSize` 取 0 = Very small，实测表现为「连线在、箭头没了」）。必须把箭头画成独立的填充三角 `ArrowHead`；规则见 `references/contract.md` 第 9 节。
- **预览不许自行补画箭头**。早期 `vsdx_preview.py` 检测到 `EndArrow` 就画个三角形，等于自己给自己打分，把产物缺陷盖住；渲染器只能如实画产物里的 Shape。
- **写底边断言排除闭合点**。取 `pts[2:-1]`；把 `(0,0)`（v=0）算进去会让每个 document 都误报「波浪越界」。
- **判断产物过期要逐部件比 ZIP 内容**，不要比文件哈希，也不要只看 mtime。
- **Visio COM 可能被安全策略拦截**。禁止实例化 COM 对象时，改用静态校验 + 反向渲染，并如实说明「Visio 自身打开未实测」，不要把自绘 SVG 说成 Visio 排版。
- **包内脚本只用标准库、自检离线可跑**；规则表是对照基线，改几何函数必须同步更新并让反向测试仍然有效。
