# Typst 讲义 → draw.io 思维导图

**技能类型**：流程型 —— 管「按什么顺序生成、生成完怎么验」，不管讲义内容怎么写、图形好不好看。

输出恒为原生 `mxGraphModel` XML，节点与连线都是可编辑 `mxCell`，不做位图化，也不依赖 draw.io Desktop。

## 先固定三件事

1. **输入**：一批 `vNN-*.typ` 讲义，按文件名中的 `NN` 升序处理。可选给出教案 docx 目录：既用它的编号给产物命名，也从它的「学习先决知识」栏取每讲的先修知识点。
2. **输出**：每讲一个 `<编号>-<讲名>.drawio`；有 docx 目录时编号取 docx 文件名，否则取讲义的 `NN`。
3. **版式**：固定为参考图的四向放射式概念图（右、左、上、下四个扇区），几何、配色、形状与关系标签一律照 `references/layout.md`，不要临场发挥。中心节点只写章名，不带编号或课次。先修节点只写知识点本身（不写「前置知识」前缀，也不写来源讲名）、文字一律绿色 `#008000`，只有教案 docx 能给，讲义里没有这条信息。

所有目录都由命令行参数给出。不要在文档或脚本里写本机绝对路径；写死路径的包一旦被复制到别的机器就是错的。

## 步骤

### 1 确认输入与编号来源

列出讲义目录里的 `vNN-*.typ`，确认数量、首尾编号与是否分卷（`02-1` 这类编号来自 docx，不来自讲义）。给了 docx 目录时，确认 docx 编号数量与讲义数量相等。

**完成标准**：讲义数量、编号序列、docx 编号序列三者已明确，且数量一致或明确记录差异原因。

### 2 生成

```bash
python scripts/typ2drawio.py --typ-dir LECTURES --docx-dir LESSONS --out-dir OUT --preview OUT/preview.html
```

无 docx 目录时省略 `--docx-dir`。需要固定时间戳做可复现对比时加 `--modified 2026-01-01T00:00:00`。

解析规则（标题层级、公式行、噪声词、示例清洗、内容密度补足）见 `references/typ-parsing.md`；XML 契约、命名规则与先修知识点提取见 `references/output-contract.md`。

**完成标准**：输出目录中每个讲义都有一个同名编号的 `.drawio`，脚本打印的统计表里主干数、知识点数均非零；给了 docx 目录时「先修知识点」列每行都有具体知识点。

### 3 跑校验

```bash
python scripts/verify_drawio.py --out-dir OUT --docx-dir LESSONS
python scripts/selfcheck.py
```

前者校验产物：XML 可解析、id 唯一、边引用有效、编号一致、无公式噪声、节点矩形零重叠、连线不穿过节点且标签不压节点、包含关系只由父指向子；给了 `--docx-dir` 时还检查先修节点是否唯一、绿色、不含「前置知识」字样与书名号、并以「支持」连线回指中心（指向中心的连线是全图唯一的向内箭头，方向校验对它单独放行）。后者校验技能包自身：文档与代码一致、样例往返、外部规则表对照。

**完成标准**：两条命令都以退出码 0 结束，且校验报告里的重叠对数、噪声条数、连线穿节点数均为 0。

### 4 目视抽查最密与最疏两张

用 `--preview` 生成的 HTML 或把预览 SVG 转成 PNG，检查主干最多的一张（例如 `09-KNN与SVM`，9 个主干）和最少的一张（例如 `07-模板匹配`，2 个主干）。重点看四角有没有挤压、中心到主干的「内容包含」标签是否被节点压住、扇区外推后的长连线是否穿过节点、先修节点是否只有知识点、连接中心的那条连线是否标 `支持`。

**完成标准**：两张图的所有关系标签完整可读，无文字溢出、无遮挡。

### 5 交付

交付 `.drawio` 源文件与预览页，说明命名规则与编号来源。本机没有 draw.io Desktop/CLI 时不要擅自安装，只交付源文件；若用户要 PNG/SVG/PDF 导出，另行处理。

**完成标准**：用户能从文件名直接看出对应哪次课，且知道预览是脚本自绘 SVG 而非 draw.io 真实导出。

## 踩坑点

- **Typst 公式行也以 `=` 开头**。把它当一级标题并清空当前分组，会让其后的整段二级知识点丢失；必须跳过公式但保留当前分组。
- **包含关系的箭头一律父指向子**。案例原先画成「案例 → 知识点」，箭头反向会让人读成子节点包含父节点；现在统一「知识点 → 案例」标 `支持`。改完要重跑校验，方向按从 `center` 出发的层级判，不靠坐标猜。
- **先修节点连中心的那条也标「支持」**，但箭头保持回指中心：先修知识点支撑本讲，方向反了就说不通。别把它一并翻成「中心 → 先修」，那会读成本讲支持前置知识；校验器对指向 `center` 的连线单独判方向，其余仍按父指向子。
- **「教学目标」「课后作业」「上节回顾」「本讲小结」不是知识点**。一级、二级各有过滤清单，混进来会让导图出现空模块。
- **中心到主干的标签必须沿连线偏向主干**（`mxGeometry x="0.62"`）。放在中点会被中心节点挡住，扇区越少越明显。
- **同一扇区里的多个主干按各自占位宽度排布，不要统一等距**。统一间距会让没有知识点的圆柱体把邻居顶到角落；四角还要再做一轮上下扇区外推，否则上/下与左/右在交界处会互相压住。
- **节点矩形重叠要做成机器可判的指标**。肉眼看着「差不多」不算，改布局后必须重跑校验，最密与最疏两种布局都要抽查。
- **先修知识点只能从教案 docx 取，不能从讲义猜**。讲义里没有「先修」这条信息；有些 docx 的「学习先决知识」小节被错填成本讲知识点，真正可靠的写法是「《上一讲章名》相关概念」这句，按它抓取才不会取错。
- **先修节点只写知识点**。章名只用于定位那一条教案记录，落图时丢掉；节点上出现「前置知识」四个字或书名号讲名，既啰嗦又会把方框撑宽、压到邻居。
- **第一环距离要按节点自身尺寸算**。若沿用主干半径，宽节点就会挤向中心、把连线标签压到节点里；用「中心半宽 + GAP_ROOT + 节点半宽」才能保持净空恒定。
- **连中心的那两类节点要放在扇区最靠轴的槽位**。圆柱体和先修节点只与中心相连，排在扇区两端就成了浅角斜线，会从相邻扇区的节点框里穿过去；挪到轴线附近后连线接近垂直，自然让开。
- **包内脚本只用标准库**，且自检离线可跑；`references/mxgraph-rules.json` 是对照基线，改 XML 结构时要同步更新它。
